# Embedded validation for the Dual-CBF compiler

This repository contains the embedded experiments accompanying the paper

> M. Kamaldar, _Extracting Exact Lie Derivatives Without Backpropagation:
> A Dual Compiler for Neural Control Barrier Functions_,
> submitted to IEEE Transactions on Control Systems Technology, 2026.

The paper introduces a dual-algebraic compiler that translates a trained
neural control barrier function (CBF) into a self-contained C++ header
that evaluates the exact safety constraint by forward propagation alone,
with zero dynamic memory allocation. The compiler itself is released as a
separate Python package: `dual-cbf-compiler` ([PyPI][pypi],
[GitHub][gh-compiler]).

This repository contains the **hardware experiments** that produce the
numerical values in Section V of the paper. Three nonlinear control
systems are validated on an ESP32-S3 microcontroller: a kinematic bicycle,
a Van der Pol oscillator, and an inverted pendulum (relative-degree 2).

[pypi]: https://pypi.org/project/dual-cbf-compiler/
[gh-compiler]: https://github.com/mkamaldar/dual_cbf_compiler

## What is in this repository

| Path                         | Purpose |
| ---                          | --- |
| `01_train_models.py`         | Trains the three neural CBFs in PyTorch and exports them to ONNX. |
| `02_compile_headers.py`      | Calls the compiler (`parse_onnx` + `emit_cpp_header`) on each ONNX file, producing one self-contained `dual_cbf.h` per example. |
| `03_run_closed_loop.py`      | Host-side closed-loop simulations for Fig. 4 (bicycle) and Fig. 6 (Van der Pol phase portrait). Compiles each generated header into a shared library via `g++` and calls it through `ctypes`. |
| `04_collect_results.py`      | Parses the captured ESP32 serial logs and writes a LaTeX macro file that fills the placeholders in the paper. Optionally patches a `.tex` source in place via `--patch-tex`. |
| `shared/timer.h`             | Cycle-accurate timer wrapper around the ESP32-S3 `CCOUNT` register. |
| `shared/reverse_mode_ad.h`   | Hand-written reverse-mode AD baseline (eq. (29) of the paper). Activation cache is heap-allocated to faithfully match what a general-purpose AD runtime does, with peak-byte tracking. |
| `<example>/main/main.cpp`    | ESP-IDF benchmark driver: runs N=1000 iterations of both methods, performs a numerical agreement check, and prints CSV results over UART. |
| `<example>/main/host_test.cpp` | Same logic compiled for the host PC with the ESP-IDF includes stubbed out — a pre-flight regression that catches wiring bugs in seconds without touching hardware. |
| `<example>/main/dual_cbf.h`  | Generated by `02_compile_headers.py`. Self-contained, zero-allocation. |
| `<example>/CMakeLists.txt`<br>`<example>/main/CMakeLists.txt`<br>`<example>/sdkconfig.defaults` | ESP-IDF build configuration. Pinned to 240 MHz, no Wi-Fi/Bluetooth, USB-Serial-JTAG console. |

The three example directories are:

- `bicycle_4_32_32_1/` — kinematic bicycle, ReLU 4-32-32-1, m=2 inputs, relative degree 1.
- `vdp_2_64_64_1/` — Van der Pol, ReLU 2-64-64-1, m=1 input, relative degree 1.
- `pendulum_2_32_32_1/` — fully actuated inverted pendulum, **Softplus** 2-32-32-1, m=1 input, relative degree 2 (hyper-dual).

## What reviewers should look at first

The substantive technical content lives in:

1. **`shared/reverse_mode_ad.h`** — the reverse-mode AD baseline against
   which the dual compiler is benchmarked. The activation cache is
   allocated from the heap on every call (`new float[]`), exactly as a
   tape-based AD runtime would. Peak heap bytes (cache + backward
   scratch) are tracked in `peak_dynamic_bytes()` and reported alongside
   the timings.
2. **`<example>/main/main.cpp`** — for each of the three examples. The
   `LinearSpec` array points at the same `static const float[]` weight
   arrays embedded by the dual compiler in `dual_cbf.h`, so both methods
   consume bit-identical inputs. Each driver runs a 32-state agreement
   check before reporting timings; if the dual compiler and the
   reverse-mode adapter ever disagree above tolerance, the driver
   prints `AGREEMENT_FAIL,...` and aborts.
3. **`<example>/main/host_test.cpp`** — the same agreement check,
   runnable on a host PC with `g++` alone. This is the fastest way to
   sanity-check the implementation without touching the MCU.

Reproducibility of the timing claims requires a physical ESP32-S3-DevKitC
board; reproducibility of the *correctness* claim does not — `make
host-test` runs in seconds and asserts that the dual compiler and the
reverse-mode AD baseline agree to single-precision machine epsilon.

## Quickstart

### 0. Hardware

- **ESP32-S3-DevKitC-1-N8R8** development board (Xtensa LX7 dual-core at
  240 MHz, 8 MB flash, 8 MB PSRAM).
- USB-C **or** micro-USB cable matching your board's port.

### 1. Host tooling

```bash
git clone https://github.com/mkamaldar/dual_cbf_esp32_experiments.git
cd dual_cbf_esp32_experiments
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
make install
```

Verify the compiler is installed:

```bash
dual-cbf-compile --help
```

### 2. ESP-IDF (one-time, ~15 min)

We use ESP-IDF v5.3. On Linux/macOS:

```bash
mkdir -p ~/esp && cd ~/esp
git clone -b v5.3 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32s3
. ~/esp/esp-idf/export.sh           # source in every new shell
```

On Windows use the offline installer at <https://dl.espressif.com/dl/esp-idf/>.

Verify:

```bash
idf.py --version       # should print "ESP-IDF v5.3.x"
```

### 3. Train, compile, host pre-flight

```bash
make train             # ~1 min (CPU): three networks, exports ONNX
make compile           # generates dual_cbf.h for each example
make host-test         # compiles and runs three regression tests
```

The host pre-flight asserts that the dual compiler and the reverse-mode AD
baseline agree numerically. Expected:

```
Worst absolute error over 64 random states: 7.629e-06
PASS
```

The pendulum test uses a **5% relative tolerance** because the reverse-mode
baseline at relative degree 2 falls back to finite-difference
Hessian-vector products (acknowledged in the paper text accompanying
Example 3).

### 4. Build, flash, capture timings

For each example, in three separate terminals (or one at a time):

```bash
. ~/esp/esp-idf/export.sh

cd bicycle_4_32_32_1
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyUSB0 flash
idf.py -p /dev/ttyUSB0 monitor | tee serial.log     # Ctrl+] to exit
```

Adjust `/dev/ttyUSB0` to match your machine (Linux: `ls /dev/ttyUSB*
/dev/ttyACM*`; macOS: `ls /dev/cu.usb*`; Windows: Device Manager). Repeat
for `vdp_2_64_64_1/` and `pendulum_2_32_32_1/`.

The benchmark output looks like:

```
========================================
Bicycle 4-32-32-1 (ReLU) benchmark
CPU = 240000000 Hz, N_ITERS = 1000
========================================
Agreement check: PASS (32 random states, |err| < 1e-3)

----- RESULTS (CSV, parsed by host) -----
DUAL_BICYCLE,0.31,0.34,0.51,0
RVAD_BICYCLE,0.62,0.65,0.99,824
----- END RESULTS -----
```

CSV format: `<method>_<example>,<min_us>,<median_us>,<max_us>,<dynamic_bytes>`.

### 5. Generate Figures 4 and 6

```bash
make sim
```

Writes `bicycle_closed_loop.pdf` and `vdp_phase.pdf`.

### 6. Fill the paper placeholders

```bash
make collect
# or, to patch the paper's .tex source in place:
python 04_collect_results.py \
    bicycle_4_32_32_1/serial.log \
    vdp_2_64_64_1/serial.log \
    pendulum_2_32_32_1/serial.log \
    --patch-tex /path/to/dual_cbf_tcst.tex
```

The script writes `paper_measurements.tex` containing
`\renewcommand{\bicycleDualUs}{...}` lines for each placeholder. With
`--patch-tex` it also rewrites the `\newcommand{...}{XX.X}` blocks in the
paper's source directly (a `.bak` file is written next to the original).

## What is measured, and how

Each `main.cpp` benchmark driver runs **N = 1000 iterations** on
freshly-sampled random states (so we exercise both branches of every
ReLU gate, not pathological all-positive inputs). Per-call cycle counts
are read from the ESP32-S3 `CCOUNT` register and converted to
microseconds at the configured 240 MHz.

The reverse-mode AD baseline:

- consumes the **same `static const float[]` weight arrays** that the
  dual compiler embedded in `dual_cbf.h` (literal pointer aliasing into
  the embedded weights), so both methods see bit-identical weights;
- allocates its activation cache from the heap (`new float[]`) the way a
  general-purpose AD runtime would, and the peak live allocation
  (cache + backward scratch) is reported as the `<dynamic_bytes>` field;
- implements the textbook backward recurrence
  `δ_{i-1} = W_iᵀ · diag(σ_i'(a_i)) · δ_i` (eq. (29) of the paper),
  followed by the inner products `∇h · f` and `∇h · G` to assemble the
  CBF safety constraint per Remark 5.

The pendulum example exercises the relative-degree-2 hyper-dual code
path (`evaluate_cbf_2nd_order`). Its reverse-mode baseline uses
finite-difference Hessian-vector products, because true
double-backpropagation does not fit on a microcontroller without
porting an entire AD runtime; this is acknowledged explicitly in the
paper text.

## Troubleshooting

- **`idf.py: command not found`** — you forgot to source `export.sh`
  (or open the ESP-IDF PowerShell on Windows).
- **`Permission denied: /dev/ttyUSB0`** on Linux — add yourself to the
  `dialout` group: `sudo usermod -aG dialout $USER` and log out/in.
- **`Could not open /dev/ttyUSB0, the port is busy`** — another `monitor`
  instance is still attached. `Ctrl+]` exits cleanly.
- **The board reboots in a loop** — try a different USB cable. Some
  cables are charge-only. Brownouts are also possible on heavy CPU load
  with cheap power supplies; use a powered hub or a quality cable.
- **`AGREEMENT_FAIL` printed in the log** — the dual compiler and
  reverse-mode adapter disagree on numerical output. This is almost
  always a wiring bug in `LinearSpec[]` (mismatched layer dimensions,
  wrong activation kind, transposed weight). Check that the array
  matches the network in `02_compile_headers.py`.
- **`'esp_cpu.h' file not found`** — you are on an ESP-IDF version older
  than 5.0. Either upgrade, or replace `esp_cpu_get_cycle_count()` with
  `xthal_get_ccount()` and include `<xtensa/hal.h>` in `shared/timer.h`.
- **`make host-test` fails to compile** — make sure `02_compile_headers.py`
  has been run first, so each `<example>/main/dual_cbf.h` exists.
